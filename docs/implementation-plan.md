# 分阶段实施与验收

原则：按完整闭环实施，架构和测试随实际行为同步；不把模型格式正确当成结论正确。

## 第一阶段：架构基础（完成）

- [x] 目录职责、前后端边界、数据模型和接口契约。
- [x] Next.js 单应用、DeepSeek 服务端接入、Prisma + PostgreSQL。
- [x] 用户事实与模型假设分开，版本冲突、影响传播、行动历史保留规则。

## 第二阶段：最小闭环（完成）

- [x] 决策列表、困境草稿、可编辑概况、少量追问。
- [x] 匿名会话隔离、保存与刷新恢复。
- [x] 真实 DeepSeek 概况整理验证，密钥不进入客户端。
- [x] 生产构建、类型检查、输入与同源校验、基础接口验证。

实际选择：使用原生语义控件和统一 CSS 变量实现界面，没有引入初期备选的 Tailwind/shadcn。会话按访问续期 90 天。

## 第三阶段：路径与情境（完成）

- [x] AI 生成 2～3 条路径，用户可增删改，上限 5 条。
- [x] 具体时间/事件、变化、困难、依据与假设。
- [x] 用户感受、假设纠正、后续问题与有限分支。
- [x] 每路径最多 6 个情境，最多 2 层后续分支，服务端强制校验。
- [x] 刷新恢复所有业务记录；真实模型路径与情境调用通过。

## 第四阶段：条件更新与一致性（完成）

- [x] 条件稳定 ID、依赖表、保守失效传播。
- [x] 标注受影响内容、更新原因及前后差异。
- [x] 原反馈保留，更新情境后标记重确认。
- [x] 假设纠正将相关情境及子情境标记待更新。
- [x] 乐观锁、请求幂等、单决策生成锁、旧输出不覆盖新内容。
- [x] 模型输出结构及引用校验；失败不破坏原内容。

概况 1200ms 自动保存，串行写入；恢复的未保存草稿需先核对后显式保存，避免覆盖其他页面的新内容。

## 第五阶段：行动与回访（完成）

- [x] 可编辑总结，允许暂不选择。
- [x] 1～3 个生成行动，包含做什么、验证什么、如何帮助判断。
- [x] 事务保证当前仅一个选定行动。
- [x] 用户记录结果，结合新信息重新生成总结。
- [x] 重新生成不删除已选行动、完成行动及结果。

路径与总结通过明确按钮保存。当前没有自动执行用户行动。

## 第六阶段：本地验证与后续改进

- [x] 业务单元测试和隔离模型服务的完整流程集成验证。
- [x] 真实模型合成案例验证。
- [x] 浏览器创建、探索、反馈、行动记录流程验证。
- [x] 本地数据库说明、迁移和启动步骤。
- [x] 会话级生成额度，任务元数据不包含提示词/输入快照。
- [ ] 扩充职业和城市选择案例，持续人工评测。
- [ ] 更多设备与完整无障碍审计、并发压力测试。
- [ ] 公网部署所需入口限流、日志和运维配置。
- [ ] 后台任务队列与逐字流式输出（当前完整 JSON）。

具体执行结果与限制见 verification.md。当前应用用于本地验证，未发布到公网。
